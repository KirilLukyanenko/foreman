**Conventions.** How code is written here, as shown by the code itself and its configuration, so a change looks
like it belongs: naming, file and folder layout for a new feature, error handling and validation, logging, async and
nullability style, dependency injection or composition, public API documentation; how tests are written (framework,
naming, fixtures, assertions, where a test for a new piece of code goes); and the commit message style from the
git facts. Where the code is inconsistent, say which way is current (newer files, most files). Point to one or two
files that are good models to copy.
